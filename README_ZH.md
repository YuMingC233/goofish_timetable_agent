# 闲鱼排期助手（Goofish Timetable Agent）

一款浏览器扩展，为[闲鱼](https://seller.goofish.com)网页工作台带来 AI 自动排期与 Notion 日历同步能力——让你告别多线程沟通的混乱，专注交付。

## 痛点

在闲鱼上接单卖服务时，交易往往是集中爆发的。一个下午可能同时聊成 8～10 单，分散在不同的对话窗口里。没有工具辅助的话，你只能：

- 反复回看每条对话，回忆答应了什么
- 凭感觉估算截止时间，在脑子里排先后
- 冒着手头两个任务"撞车"的风险
- 忘了哪个买家要的是什么

本扩展解决的就是这个问题——它**嵌入在闲鱼聊天页面旁边**，通过 AI 从每条对话中提取结构化任务信息，自动检测排期冲突，并在人工审核一键确认后同步到 Notion 日历数据库。

### 核心模块

| 模块 | 职责 |
|--------|---------------|
| **DOM 抓取器** | 从闲鱼页面结构中提取聊天消息、买家昵称、时间戳。监听 DOM 变化以捕获新消息。 |
| **AI 提取器** | 将抓取到的对话文本发送给大语言模型（LLM），结合结构化 Prompt 返回 JSON：`{buyer, requirement, urgency, price, estimatedHours}`。支持多供应商（OpenAI、Claude、本地模型）。 |
| **冲突检测器** | 给定新任务的起止时间，与已有排期任务逐一比对，标记时间重叠——已内置 10 分钟缓冲。 |
| **排期优化器** | 推荐最早可用的无冲突时间段。按"紧急程度 × 截止时间紧迫度"加权排序。 |
| **Notion 同步** | 在 Notion 日历数据库中创建/更新页面。将提取字段映射到 Notion 属性列。支持 OAuth 或 Integration Token 两种鉴权方式。 |
| **悬浮球 UI** | 注入到闲鱼页面的可拖动 `<div>`。角标显示待处理任务数。点击切换弹出面板。 |
| **弹出面板** | 核心交互界面——自动填充的表单、冲突警告、编辑控件、导出按钮。使用 Shadow DOM 构建，避免样式污染宿主页面。 |

## Notion 数据库 Schema

目标 Notion 数据库应包含以下属性列：

| 属性 | 类型 | 描述 |
|----------|------|-------------|
| **任务名称** | 标题 | 自动生成：`[买家] - [需求摘要]` |
| **买家** | 富文本 | 闲鱼用户名 |
| **需求** | 富文本 | 完整需求描述 |
| **紧急程度** | 选择 | `🔴 紧急` / `🟡 中等` / `🟢 不急` |
| **价格 (¥)** | 数字 | 约定价格（人民币） |
| **预估工时** | 数字 | 预计工作时间（小时） |
| **日期** | 日期 | 排期日期（日历视图锚点） |
| **开始时间** | 日期（含时间） | 任务开始时间 |
| **结束时间** | 日期（含时间） | 任务结束时间（已含 10 分钟缓冲） |
| **状态** | 选择 | `📋 已排期` / `🔄 进行中` / `✅ 已完成` / `❌ 已取消` |
| **聊天链接** | URL | 跳转回闲鱼对应对话的深链接 |
| **备注** | 富文本 | 人工审核时添加的备注信息 |

## AI Prompt 设计

发送给 LLM 的核心提取 Prompt：

```
你是一个排期助手。给定一段闲鱼对话，提取结构化数据。

对话内容：
---
{chat_messages}
---

仅返回合法的 JSON（不要 markdown，不要解释）：
{
  "buyerName": "字符串",
  "requirement": "用中文简洁概括需求",
  "urgency": "high" | "medium" | "low",
  "urgencyReason": "判定紧急程度的简要理由（引用原话关键词）",
  "price": 数字或 null,
  "estimatedHours": 数字,
  "deadline": "ISO 日期字符串或 null",
  "specialNotes": "任何约束条件或特殊要求"
}
```

### 紧急程度判定规则（同时作为后备规则编码）

| 信号 | 紧急程度 |
|--------|---------|
| "急" / "尽快" / "马上" / "今天" / "明天" / 截止时间在 48 小时内 | 🔴 紧急 |
| "这周" / "本周" / "几天内" / 截止时间在 7 天内 | 🟡 中等 |
| 未提及时间压力 / "不急" / "有空再做" | 🟢 不急 |

### 价格 × 紧急程度 调节规则

```
如果 紧急程度 == "high"   → 建议价格 = max(抓取到的价格, 默认基础价 × 1.3)
如果 紧急程度 == "medium" → 建议价格 = max(抓取到的价格, 默认基础价 × 1.0)
如果 紧急程度 == "low"    → 建议价格 = max(抓取到的价格, 默认基础价 × 1.0)
```

这条规则编码了运营策略：**紧急任务溢价**

## 冲突检测算法

```
给定：  new_task(start, end)  // 其中 end 已包含 +10 分钟缓冲
        existing_tasks[]      // 每个均有 (start, end)

对每个 existing_task：
    如果 new_task.start < existing_task.end 且 new_task.end > existing_task.start：
        → 冲突（时间重叠）

建议解决：
    earliest_slot = 当前时间
    对每个 existing_task（按 start 排序）：
        如果 earliest_slot + new_task.duration <= existing_task.start：
            return earliest_slot   // 找到可用空档
        earliest_slot = max(earliest_slot, existing_task.end)
    return earliest_slot           // 排在所有已有任务之后
```

10 分钟缓冲确保不会出现前一个任务刚结束、下一个任务立即开始的情况——给每个任务之间留出喘息空间。

## 环境搭建与开发

### 前置条件

- Node.js 18+（通过 nvm 管理）
- pnpm（项目约定）
- 一个 Notion Integration Token（[在此创建](https://www.notion.so/my-integrations)）
- 一个 OpenAI API Key（或 Anthropic / 本地 Ollama 端点）
- 一个 Notion 日历数据库（复制模板——链接待定）

### 快速开始

```bash
# 克隆
git clone <repo-url> && cd goofish_timetable_agent

# 安装依赖
pnpm install

# 配置环境变量
cp .env.example .env
# 填入：NOTION_TOKEN, OPENAI_API_KEY, NOTION_DATABASE_ID

# 开发模式（监听 + 热重载扩展）
pnpm dev

# 在 Chrome 中加载
# 1. 打开 chrome://extensions
# 2. 开启「开发者模式」
# 3. 点击「加载已解压的扩展程序」→ 选择 dist/ 目录

# 测试
pnpm test          # 单元测试
pnpm test:e2e      # 端到端测试（需要 Chrome）
```

### 构建

```bash
pnpm build          # 生产构建 → dist/
pnpm build:zip      # 打包 zip 用于 Chrome Web Store 提交
```

## 隐私与安全

- **所有 AI 调用直接从你的浏览器发出**，直达配置的 API 端点。中间没有任何第三方服务器中转。
- **Notion Token 和 API Key** 存储在 Chrome `storage.local` 中（由操作系统层面加密）。
- **聊天内容仅即时处理**——除非用户主动导出到 Notion，否则不持久化任何对话数据。
- 本扩展仅在 `*.goofish.com` 和 `*.taobao.com`（闲鱼所属域）下激活。
